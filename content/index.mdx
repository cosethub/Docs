# Introduction

CoSet connects **credentials**, **workflows**, **warehouses**, **views**, and **file stores** so operations teams can move data securely — on a schedule or on demand — without hard-coding passwords into every job.

Use it when you would otherwise spend engineering time on SFTP clients, credential vaults, schedulers, alert wiring, and one-off scripts for every counterparty. CoSet supplies that plumbing so your team can focus on **ops outcomes**: breaks, prices, positions, NAV packs, and sign-offs.

For a first hands-on path, see [Getting started](./getting-started).

## Why not build it yourself

| You would otherwise build… | CoSet already has… |
| --- | --- |
| Per-vendor connectors (SFTP, IMAP/SMTP, SQL, Geneva, Bloomberg, Power BI, HTTP, …) | **Pre-built job types** and credential types — pick, configure, schedule |
| A secrets store and rotation story for every script | **Credential Hub** — shared org credentials, secrets never returned on read |
| Ad-hoc “does this login still work?” checks | **Credential validation** on a daily/weekly cadence with notification groups |
| Cron + custom failure email for each pipeline | **Workflow trees** with schedules and **On success / On failure / Always** branches |
| Homegrown file watchers and mailbox monitors | **FTP Monitor**, **File Monitor**, **Email Check**, **Quick Email Monitor**, and related jobs |
| Spreadsheet or script checks for bad warehouse rows | **[Data monitors](/warehouses/data-monitors)** on tables/views → status, trigger job, and **[webhooks](/api/webhooks)** |
| One-off SQL/views for each recon | **Views** (joins, filters, aggregates) plus **AI-assisted** drafting |
| Glue code so internal tools can trigger the same work | **[Public API](/api)** and webhooks against the same jobs and warehouses |

**What you keep owning:** business rules — what a break means, which extract the FA expects, who signs off, which prices to repair. CoSet runs the movement, storage, monitoring, and alerting around those rules.

## What CoSet does

| Capability | What it is for |
| --- | --- |
| **Credential Hub** | Store logins, connection strings, and API details once; jobs and warehouses pick them by name |
| **Workflows** | Chain jobs into trees (download → transform → load → notify) with schedules and success/failure branches |
| **Warehouses** | Hold structured data (SQL Server, PostgreSQL, and related staging); browse tables/views and set data monitors |
| **Views** | Shape warehouse tables into reusable datasets — joins, filters, calculated columns, aggregates |
| **File stores** | Browse, upload, download, and organize files that workflows produce or consume |
| **Public API** | Call the same surfaces from schedulers, scripts, internal tools, or MCP clients |
| **Coordinator & AI** | Plan setup work and draft warehouse views in natural language |

## How the pieces work together

Most day-to-day automation follows this loop:

```
Credential Hub
      │
      ▼
Workflows (Bridge runs jobs)
      │
      ├──► File stores   (raw files in / out)
      │
      └──► Warehouses    (tables loaded / queried)
                │
                ▼
              Views      (shaped datasets)
                │
                ▼
         Workflows again (e.g. Table to CSV → Email / SFTP)
```

1. **Credentials** unlock mail, FTP/SFTP, databases, Geneva, Bloomberg, OAuth providers, and more.
2. **Workflows** use those credentials. A **Bridge** (process agent) executes each job.
3. Jobs land files in a **file store**, load rows into a **warehouse**, or both.
4. **Views** turn warehouse tables into the shapes ops and reporting need.
5. Later workflows can **export a view** (for example Table to CSV) and send it out.

The **Public API** and **Coordinator** sit alongside this loop: they read and write the same warehouses, jobs, chats, and file stores your UI uses.

## Core building blocks

### Credentials

**Credential Hub** is the secure place for connection details. Prefer shared org credentials for production workflows so jobs do not embed secrets. Secrets are stored for job use and are **never returned** when you list or open a credential. Turn on validation when you want the bridge to prove connections still work and notify a group on failure.

→ [Credentials](/credentials)

### Workflows

A workflow is a **tree of jobs**. The root is usually a **Group**. Children run on a schedule or when the parent finishes (**On success**, **On failure**, or **Always**). Job types cover email, FTP, encryption, Geneva, Bloomberg, SQL loads, Table to CSV, Data Review, monitors, and many more.

→ [Workflows](/workflows)

### Warehouses and views

Warehouses store the structured data your pipelines produce. Browse **Tables / Views** in CoSet DB, set [data monitors](/warehouses/data-monitors) on exception rows, and build **Views** (joins, filters, calculated and aggregate columns). Workflows can export a view the same way they export a table.

→ [Warehouses](/warehouses) · [Views](/views)

### File stores

File stores hold the documents and extracts workflows download, transform, or transmit. Browse and manage them in the UI or through the [file stores API](/api/file-stores).

### API and AI surfaces

| Surface | Use when |
| --- | --- |
| [Public API](/api) | You need REST access to warehouses, file stores, jobs, workflows, and webhooks |
| Coordinator | You want guided plans for credentials, warehouses, and related setup |
| [AI views](/views/ai-views) | You want to draft a warehouse view by chatting |

## Typical journeys

| Goal | Path |
| --- | --- |
| Pull counterparty files daily | Credential (SFTP) → FTP Download → optional decrypt/convert → File store |
| Load files into SQL | File in store → SQL Bulk Load / related job → Warehouse table |
| Publish a shaped extract | View on warehouse → Table to CSV → Email or FTP Transmit |
| Review exceptions | Workflow → Data Review Task → notify on failure |
| Alert on bad rows in a table/view | [Data monitors](/warehouses/data-monitors) → status / trigger job / [webhooks](/api/webhooks) |
| Automate from outside the UI | OAuth token → Public API run job / query warehouse |
