# Workflows

Workflows chain jobs into a **tree**: a parent runs, then children run based on success, failure, or always.

Open **Workflow Automation** to create, edit, and run workflows.

## In this section

## Big picture

```
Group (workflow title)
 └── Job A   [schedule or trigger]
      └── Job B   [On success]
           └── Job C   [On success]
      └── Notify   [On failure]
```

Each node is a **job type** (Email Check, FTP Download, Table to CSV, Data Review Task, and many more).

## Before you begin

- You need access to **Job Workflow** / Process Server.
- Jobs that talk to mail, FTP, or databases need credentials in **Credential Hub**.
- A **Bridge** must be available to run the jobs.
