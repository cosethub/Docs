# MCP server (coming soon)

CoSet hosts a public [MCP](https://modelcontextprotocol.io/) endpoint on your tenant so Claude, Cursor, and other agents can run workflows, query warehouses, triage data-monitor alerts, and work period-close checklists — without installing a local adapter or reimplementing REST in every prompt.

The hosted server is a thin tool layer over `/api/v1`. Same scopes, permissions, and side effects as the Public API.

## What the MCP server is

```
Agent (Claude / Cursor / internal bot)
        │
        ▼
  https://{tenant}.cosethub.com/mcp   ← CoSet-hosted (Streamable HTTP / SSE)
        │
        ▼
  https://{tenant}.cosethub.com/api/v1
        │
        ▼
  Bridge · warehouses · ProcessServer · …
```

Each **MCP tool** wraps one REST call (or a fixed, documented sequence such as start export → poll export). The server does not embed business logic that the API does not already enforce.

You point the MCP client at the tenant URL and authenticate once. CoSet holds the adapter; the agent never talks to `/api/v1` directly unless you also use REST from scripts.

## Endpoint

| | |
| --- | --- |
| **URL** | `https://{tenant}.cosethub.com/mcp` |
| **Transport** | Streamable HTTP (preferred) or SSE, per MCP remote-server support in the client |
| **Docs metadata** | Server advertises [llms.txt](https://cosethub.github.io/Docs/llms.txt) for agent discovery |

Replace `{tenant}` with your CoSet hostname prefix (same as the Public API base URL).

## In scope

Everything documented under Public API **except**:

| Excluded | Reason |
| --- | --- |
| [Auth & account](./auth) (`/health`, `/oauth/token`, `/me`, `/organizations/*`) | Auth is **how the client connects** to MCP, not a tool the model calls. Token / API key lives in the MCP client config. |
| [Webhooks & events](./webhooks) | Webhooks are **push subscriptions** for your infrastructure (HTTPS callback URL, signing secret, retry policy). Agents should **poll** runs and alerts (`coset_get_job_run`, `coset_list_data_monitor_alerts`) or you run a separate webhook receiver — not register webhooks from inside the IDE. |

## Authentication

The agent never sees your secret. The MCP **client** (Cursor, Claude Desktop, etc.) sends credentials on each session; the hosted server validates them and calls `/api/v1` with the same org and scopes.

| Method | When to use |
| --- | --- |
| **OAuth Bearer** (API client → `POST /oauth/token`) | Preferred for org-scoped tools; same client as Public API |
| **API key** / job access key | Narrow keys (for example `X-Access-Key` for `run_job` only) where the dashboard issues them |
| **Read Only** key or flag | Hosted server registers **read tools only** — write tools are hidden |

**No MCP tools** for `POST /oauth/token` or token refresh — the client supplies a token (or the host refreshes using client credentials configured for that MCP connection). On connect, the server may call `GET /me` to resolve org id and scopes; write tools fail fast with 403 if scope is missing.

If the API key has an **IP allow list**, allow the egress IPs of the MCP **client** host (the machine or cloud runner that opens the MCP session), not a separate “MCP package” host — CoSet’s MCP endpoint is already on your tenant.

See [Auth & account](./auth) and the [API overview](./index) for issuing clients and keys.

## Connect (Cursor / Claude)

When the endpoint is live, add the tenant MCP URL to your client. Exact JSON keys vary by client version; the pattern is a **remote** MCP server with auth headers (not a local `command` / stdio process).

### Cursor (remote MCP)

```json
{
  "mcpServers": {
    "coset": {
      "url": "https://{tenant}.cosethub.com/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_ACCESS_TOKEN"
      }
    }
  }
}
```

Replace `{tenant}` and the token. Prefer a short-lived OAuth access token from [Auth & account](./auth); rotate via your secrets store rather than committing the value.

### What happens in chat

1. You ask: *“List our workflows”* or *“Run job 1042 with AsOfDate 2026-09-02”*.
2. The **model** chooses a tool name and JSON arguments (it does not receive your token).
3. The **MCP client** sends the tool call to `https://{tenant}.cosethub.com/mcp`.
4. The **hosted server** authorizes the session and calls CoSet REST.
5. JSON/text comes back through MCP → model → reply.

To poll a run, use `coset_get_job_run` (`GET /job-runs/{runId}`) — see [Jobs & workflows — read](./jobs-workflows-read).

### Claude Desktop / other hosts

Same idea: remote MCP URL + Bearer (or API key) header. Follow the host’s docs for remote / HTTP MCP servers once CoSet publishes the transport details with GA.

## Tool design rules

1. **One REST mapping per tool** unless polling is explicit (export status).
2. **snake_case** arguments matching Public API JSON.
3. Tool descriptions state **side effects** (“starts Bridge execution”, “soft-deletes monitor”).
4. Write tools require **`idempotency_key`** where the REST API supports it.
5. **Never return credential secrets** — same as API; list/get credential tools return metadata only.
6. Large list responses: pass through API pagination (`page`, `page_size`); do not auto-fetch all pages unless a dedicated `list_all_*` tool is documented as such.

Tool names use prefix `coset_` and snake_case, e.g. `coset_run_job`.

## Rollout phases

| Phase | Tool groups |
| --- | --- |
| **1 — Run & debug** | Jobs & workflows read + `coset_run_job` + `coset_request_job_error_analysis` / run-id variant + error analysis reads |
| **2 — Data & alerts** | Warehouse query/export read + data monitor alerts |
| **3 — Close** | Checklists run, history, reset |
| **4 — Platform** | Credentials, file stores, permissions, workflow create, AI chat |

Phase 1 is enough to trigger and debug workflows from Claude/Cursor against the hosted URL.

## Safety

- Honor API key **Read Only** and **Users**-linked permissions — hide write tools or pass through 403.
- Respect **IP allow list** on the MCP **client** egress IP.
- Do not log Bearer tokens, `X-Access-Key`, or credential `data` payloads.
- `coset_run_job` and `coset_run_checklist_item` are **production side effects** — descriptions must say so.
- Poll `coset_get_job_run` with backoff; do not hammer list endpoints in a tight loop.

## Local / self-hosted adapter (optional)

Most teams should use the **hosted** endpoint above. A local stdio adapter (your process calls `/api/v1` with a token) remains useful for:

- Developing against a private network or stub API before the tenant MCP URL is enabled
- Air-gapped agent hosts that cannot reach `*.cosethub.com/mcp` but can reach `/api/v1`

That path is not the product default. Prefer REST from scripts ([Trigger from scripts](/automate/trigger-from-scripts)) or wait for the hosted MCP URL.
