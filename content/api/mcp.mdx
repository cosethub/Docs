# MCP server (coming soon)

Expose CoSet’s Public API as an [MCP](https://modelcontextprotocol.io/) tool server so Claude, Cursor, and other agents can run workflows, query warehouses, triage data-monitor alerts, and work period-close checklists — without reimplementing REST in every prompt.

This page is the **product spec** for that layer: scope, tool catalog, and rollout. Implementation lives in a separate `coset-mcp` package; it is a thin adapter over `/api/v1`.

  **Coming soon.** The `coset-mcp` package and full [tool catalog](#tool-catalog) are not shipped yet. MCP tools will map 1:1 to the Public API once both are available. For early access, email [Sales@ryanbts.com](mailto:Sales@ryanbts.com). Agent-facing product docs: [Automate with CoSet](/automate) · [llms.txt](https://cosethub.github.io/Docs/llms.txt).
</Callout>

## What the MCP server is

```
Agent (Claude / Cursor / internal bot)
        │
        ▼
  coset-mcp-server          ← tools, resources, prompts
        │
        ▼
  https://{tenant}.cosethub.com/api/v1
        │
        ▼
  Bridge · warehouses · ProcessServer · …
```

Each **MCP tool** wraps one REST call (or a fixed, documented sequence such as start export → poll export). The server does not embed business logic that the API does not already enforce.

## In scope

Everything documented under Public API **except**:

| Excluded | Reason |
| --- | --- |
| [Auth & account](./auth) (`/health`, `/oauth/token`, `/me`, `/organizations/*`) | Auth is **server configuration**, not an agent tool. The MCP process holds a Bearer token or job API key issued outside the session. |
| [Webhooks & events](./webhooks) | Webhooks are **push subscriptions** for your infrastructure (HTTPS callback URL, signing secret, retry policy). Agents should **poll** runs and alerts (`get_job_run`, `list_data_monitor_alerts`) or you run a separate webhook receiver that calls MCP — not register webhooks from inside the IDE. |

## Authentication model

The MCP server is configured once per tenant:

| Config | Purpose |
| --- | --- |
| `COSET_TENANT` or `COSET_BASE_URL` | `https://{tenant}.cosethub.com/api/v1` |
| `COSET_ACCESS_TOKEN` | OAuth Bearer token (preferred for org-scoped tools) |
| `COSET_JOB_ACCESS_KEY` | Optional narrow key for `run_job` only (`X-Access-Key`) |
| `COSET_READ_ONLY=true` | Hide all write tools at registration time |

**No MCP tools** for `POST /oauth/token` or token refresh — implement refresh inside the server (client credentials on startup, refresh before expiry). Call `GET /me` once at startup to log org id and scopes; fail fast if a write tool is invoked without scope.

IP allow lists on API keys apply to the MCP host’s egress IP — document this in the MCP README.

## Quick start (Python)

The model never sees your token. You run a **small Python process** that speaks MCP on **stdio**; Cursor or Claude Desktop launches it and forwards tool calls. The process reads `COSET_ACCESS_TOKEN` from the environment and calls `/api/v1`.

<Callout type="info">
  Below is a **minimal sketch** (two tools). Production should use the planned `coset-mcp` package with the full [tool catalog](#tool-catalog). Requires the Public API enabled for your tenant.
</Callout>

### 1. Install

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install "mcp[cli]" httpx
```

Uses the official [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk) (`mcp.server.fastmcp`). Pin `mcp` in your own project when you harden this for production.

### 2. Minimal server (`coset_mcp_server.py`)

```python
"""Tiny CoSet MCP adapter — list workflows and run a job."""
import json
import os

import httpx
from mcp.server.fastmcp import FastMCP

BASE_URL = os.environ.get(
    "COSET_BASE_URL",
    f"https://{os.environ['COSET_TENANT']}.cosethub.com/api/v1",
)
TOKEN = os.environ["COSET_ACCESS_TOKEN"]

mcp = FastMCP("coset")


def _headers() -> dict[str, str]:
    return {"Authorization": f"Bearer {TOKEN}"}


@mcp.tool()
def coset_list_workflows(page: int = 1, page_size: int = 25) -> str:
    """List workflow roots. Read-only."""
    with httpx.Client(timeout=30.0) as client:
        response = client.get(
            f"{BASE_URL}/workflows",
            headers=_headers(),
            params={"page": page, "page_size": page_size},
        )
        response.raise_for_status()
        return json.dumps(response.json(), indent=2)


@mcp.tool()
def coset_run_job(
    job_id: int,
    parameter_overrides: list[dict] | None = None,
) -> str:
    """Trigger a job on the Bridge. Production side effect — returns run_id to poll."""
    body: dict = {}
    if parameter_overrides:
        body["parameter_overrides"] = parameter_overrides
    with httpx.Client(timeout=60.0) as client:
        response = client.post(
            f"{BASE_URL}/jobs/{job_id}/run",
            headers={**_headers(), "Content-Type": "application/json"},
            json=body,
        )
        response.raise_for_status()
        return json.dumps(response.json(), indent=2)


if __name__ == "__main__":
    mcp.run(transport="stdio")
```

Token refresh: for a long-lived setup, fetch `POST /oauth/token` once at startup (or on 401) inside this process — still **not** exposed as an MCP tool. See [Auth & account](./auth).

### 3. Wire into Cursor

Project or user MCP config (path to your venv Python and script):

```json
{
  "mcpServers": {
    "coset": {
      "command": "/absolute/path/to/.venv/bin/python",
      "args": ["/absolute/path/to/coset_mcp_server.py"],
      "env": {
        "COSET_TENANT": "your-tenant",
        "COSET_ACCESS_TOKEN": "your-bearer-token"
      }
    }
  }
}
```

Replace paths and secrets. If the API dashboard has **IP restriction** on, allow the machine running Cursor.

Restart Cursor (or reload MCP). The host spawns the script, calls `list_tools`, and shows `coset_list_workflows` / `coset_run_job` to the model.

### 4. What happens in chat

1. You ask: *“List our workflows”* or *“Run job 1042 with AsOfDate 2026-09-02”*.
2. The **model** chooses a tool name and JSON arguments (it does not receive your token).
3. **Cursor** sends the tool call to your Python process over stdio.
4. The **server** adds `Authorization: Bearer …` and calls CoSet REST.
5. JSON/text comes back through MCP → model → reply.

To poll a run, add `coset_get_job_run` the same way (`GET /job-runs/{runId}`) — see [Jobs & workflows — read](./jobs-workflows-read).

### 5. Test without an IDE

With the [MCP Inspector](https://github.com/modelcontextprotocol/inspector) or `mcp dev coset_mcp_server.py`, you can invoke tools manually before connecting Cursor.

## Tool design rules

1. **One REST mapping per tool** unless polling is explicit (export status).
2. **snake_case** arguments matching Public API JSON.
3. Tool descriptions state **side effects** (“starts Bridge execution”, “soft-deletes monitor”).
4. Write tools require **`idempotency_key`** where the REST API supports it.
5. **Never return credential secrets** — same as API; list/get credential tools return metadata only.
6. Large list responses: pass through API pagination (`page`, `page_size`); do not auto-fetch all pages unless a dedicated `list_all_*` tool is documented as such.

Tool names use prefix `coset_` and snake_case, e.g. `coset_run_job`.

## Rollout phases

| Phase | Tool groups |
| --- | --- |
| **1 — Run & debug** | Jobs & workflows read + `coset_run_job` + error analysis |
| **2 — Data & alerts** | Warehouse query/export read + data monitor alerts |
| **3 — Close** | Checklists run, history, reset |
| **4 — Platform** | Credentials, file stores, permissions, workflow create, AI chat |

Phase 1 is enough to trigger and debug workflows from Claude/Cursor.

## Safety

- Honor API key **Read Only** and **Users**-linked permissions — hide write tools or pass through 403.
- Respect **IP allow list** on the MCP host egress IP.
- Do not log Bearer tokens, `X-Access-Key`, or credential `data` payloads.
- `run_job` and `run_checklist_item` are **production side effects** — descriptions must say so.
- Poll `get_job_run` with backoff; do not hammer list endpoints in a tight loop.
