# Recipes

List the recipe catalog, read one recipe, and apply it into a tenant.

> **Base:** `/api/v1`  
> **Auth:** `Authorization: Bearer {token}`  
> **Scopes:** `recipes:read` / `recipes:write`

A recipe is a parameterized template. Applying it creates the workflow, view, data monitor, or checklist the template describes. The caller supplies credential ids, warehouse ids, table names, and recipients. The recipe does not embed secrets.

The human-readable catalog, with the same ids, is [Recipes](/recipes).

<Callout type="info">
  **Coming soon.** These routes are not deployed. Until they ship, `GET` and `POST` return `501` with `code: not_implemented`. The hosted MCP server does not register the recipe tools yet.
</Callout>

## Endpoints

| Method | Path | Action |
| --- | --- | --- |
| `GET` | [`/recipes`](#get-recipes) | List the catalog |
| `GET` | [`/recipes/{recipeId}`](#get-recipesrecipeid) | One recipe and its parameters |
| `POST` | [`/recipes/{recipeId}/apply`](#post-recipesrecipeidapply) | Create the resources in this tenant |
| `GET` | [`/recipe-applies/{applyId}`](#get-recipe-appliesapplyid) | Poll an apply |

## Shared types

### `RecipeSummary`

| Field | Type | Description |
| --- | --- | --- |
| `id` | `string` | Stable slug, for example `position-break-recon` |
| `name` | `string` | Display name |
| `summary` | `string` | One line on what applying it stands up |
| `creates` | `string[]` | `workflow`, `view`, `data_monitor`, `checklist` |
| `docs_path` | `string` | Anchor on [Recipes](/recipes) |

### `RecipeParameter`

| Field | Type | Description |
| --- | --- | --- |
| `name` | `string` | Argument name on apply |
| `type` | `string` | `string`, `integer`, `boolean`, or `string[]` |
| `required` | `boolean` | |
| `description` | `string` | |
| `default_value` | `any` | Present when the recipe has a default |

### `RecipeDetail`

`RecipeSummary` plus:

| Field | Type | Description |
| --- | --- | --- |
| `parameters` | `RecipeParameter[]` | Filled in on apply |
| `resources` | `object` | What a successful apply creates. Shape depends on `creates` |

### `RecipeApply`

| Field | Type | Description |
| --- | --- | --- |
| `apply_id` | `string` | Opaque id |
| `recipe_id` | `string` | |
| `status` | `string` | `pending`, `running`, `completed`, `failed` |
| `name` | `string` | Name requested for the root resource |
| `created` | `object` | Populated when `status` is `completed` |
| `error` | `string \| null` | Present when `status` is `failed` |
| `created_at` | `string` | ISO 8601 |
| `completed_at` | `string \| null` | ISO 8601 |

`created` uses whichever keys the recipe produces:

| Key | Type | When |
| --- | --- | --- |
| `workflow_id` | `integer` | A workflow was created |
| `view_qualified_names` | `string[]` | Views were created |
| `data_monitor_ids` | `integer[]` | Data monitors were created |
| `checklist_id` | `integer` | A checklist was created |

## `POST /recipes/{recipeId}/apply`

Create the recipe’s resources in the caller’s organization. Production side effect. Does not run the new workflow unless `run_after_apply` is true.

| | |
| --- | --- |
| **Status** | Coming soon |
| **Scopes** | `recipes:write` |

The caller also needs the underlying access for each resource the recipe creates (Workflow Automation, Database Views, data monitors, or checklists).

#### Headers

| Name | Required | Description |
| --- | --- | --- |
| `Idempotency-Key` | No | UUID. A retry with the same key and body returns the original apply |

#### Request body

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | `string` | Yes | Name for the root workflow or checklist |
| `parameters` | `object` | Yes | Values for the recipe’s `parameters` |
| `run_after_apply` | `boolean` | No | Default `false`. When `true`, start the new workflow after create |

#### Response `202 Accepted`

```json
{
  "apply_id": "rpa_4c91e2",
  "recipe_id": "position-break-recon",
  "status": "pending",
  "name": "Daily book vs custodian breaks",
  "created": {},
  "error": null,
  "created_at": "2026-11-09T16:40:00Z",
  "completed_at": null
}
```

Poll [`GET /recipe-applies/{applyId}`](#get-recipe-appliesapplyid).

#### Errors

| HTTP | `code` | When |
| --- | --- | --- |
| `404` | `not_found` | Unknown recipe |
| `422` | `validation_error` | Missing parameter, unknown table, or a credential id the caller cannot use |
| `501` | `not_implemented` | Route not deployed yet |

### Examples

#### Position breaks

Stands up `ref.position_breaks` with `Diff <> 0` and `AsOfDate` from **Beginning of day** to **End of day**. Table to CSV exports that view, Data Review Task is the personal sign-off, and Email sends the CSV after approval. A monitor stays on the view. Walkthrough: [position-break-recon](/recipes#position-break-recon).

<Tabs items={['JavaScript', 'Python']}>
  <Tabs.Tab>

```js
const response = await fetch(
  "https://portal.cosethub.com/api/v1/recipes/position-break-recon/apply",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.ACCESS_TOKEN}`,
      "Content-Type": "application/json",
      "Idempotency-Key": "a4e8c1d0-6b32-4f90-9c17-2d5b8e0a6f44",
    },
    body: JSON.stringify({
      name: "Daily book vs custodian breaks",
      run_after_apply: false,
      parameters: {
        warehouse_id: 7,
        book_table: "book_positions",
        custodian_table: "custodian_positions",
        book_qty_column: "BookQty",
        custodian_qty_column: "CustodianQty",
        key_columns: ["AsOfDate", "Account", "Security"],
        trade_date_column: "AsOfDate",
        date_start_preset: "Beginning of day",
        date_end_preset: "End of day",
        schema: "ref",
        view_name: "position_breaks",
        email_to: ["ops-recon@example.com"],
      },
    }),
  },
);

const data = await response.json();
```

The view keeps `TradeDate` from **Beginning of day** to **End of day**. Data Review Task is the personal sign-off. Table to CSV exports `View: ref.manual_trades` only after approval, and Email attaches that file. Walkthrough: [data-request-signoff](/recipes#data-request-signoff).

## `GET /recipe-applies/{applyId}`

Poll an apply started by [`POST /recipes/{recipeId}/apply`](#post-recipesrecipeidapply).

| | |
| --- | --- |
| **Status** | Coming soon |
| **Scopes** | `recipes:read` |

#### Response `200 OK`

```json
{
  "apply_id": "rpa_4c91e2",
  "recipe_id": "position-break-recon",
  "status": "completed",
  "name": "Daily book vs custodian breaks",
  "created": {
    "workflow_id": 1204,
    "view_qualified_names": ["ref.position_breaks"],
    "data_monitor_ids": [88]
  },
  "error": null,
  "created_at": "2026-11-09T16:40:00Z",
  "completed_at": "2026-11-09T16:40:18Z"
}
```

When `run_after_apply` was true and the apply created a workflow, `created` also includes `run_id`. Poll that run with [`GET /job-runs/{runId}`](./jobs-workflows-read#get-job-runsrunid).
