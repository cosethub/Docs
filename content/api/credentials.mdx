# Credentials

Create, update, delete, and test Credential Hub entries.

> **Base:** `/api/v1`  
> **Auth:** `Authorization: Bearer {token}`  
> **Scopes:** `credentials:read` (list/get), `credentials:write` (create/update/delete/test)  
> **Legacy:** ProcessServer websocket ops (`CreateCredential`, `UpdateCredential`, `DeleteCredential`, `ValidateCredential`, `ValidateUpdatedCredential`)

Today these mutations run over the ProcessServer session with **Credentials** component write access. Public REST wraps them under `/credentials/*`.

**Secrets are write-only.** Credential Hub **never returns** passwords, keys, connection strings, or other secret field values. List and detail responses are **names and metadata only** (`id`, `name`, type, sharing, validation status). Clients send `data` on write; the API does not echo it back.

Product UI: [create a credential](/getting-started#2-create-a-credential).

---

## Shared types

### `CredentialDataEntry`

Type-specific connection fields (host, username, password, and so on). Keys depend on `credential_type_id`.

**Write-only.** Include on create/update (and optional test-with-update). Omitted from every response.

| Field | Type | Description |
| --- | --- | --- |
| `key` | `string` | Setting name |
| `value` | `string` | Setting value (may be secret; accepted on write only) |

Legacy websocket sends `Data` as `KeyValuePair<string, string>[]` on write. Responses still omit secret values.

### `Credential`

Metadata returned after create/update and on list/detail surfaces. **Never includes `data` or secret values.**

| Field | Type | Description |
| --- | --- | --- |
| `id` | `integer` | Credential ID |
| `name` | `string` | Display name |
| `description` | `string \| null` | Optional description |
| `credential_type_id` | `integer` | Type (FTP/SFTP, Email IMAP, SQL Server, …) |
| `credential_type_name` | `string \| null` | Type label when returned from list/create |
| `is_shared` | `boolean` | Shared with organization |
| `is_default` | `boolean` | Default for this type in the org |
| `is_read_only` | `boolean \| null` | Read-only flag |
| `is_cloud_accessible` | `boolean \| null` | Cloud-accessible flag |
| `is_validation_enabled` | `boolean \| null` | Periodic validation on |
| `frequency_id` | `integer \| null` | `1` = Daily, `2` = Weekly |
| `group_id` | `integer \| null` | Notification group for validation failures |
| `is_valid` | `boolean \| null` | Last validation result |
| `validation_completed_on` | `string \| null` | ISO 8601 when last validated |
| `roles` | `string[]` | Role names with access |
| `permissions` | `string[]` | `{RoleName}_{PermissionName}` entries |

| Field | Type | Required | Description |

| `roles` | `string[]` | No | |
| `permissions` | `string[]` | No | |

Same fields as create, plus validation schedule fields. `id` is in the path.

| Field | Type | Required | Description |

| `credential_type_id` | `integer` | Yes | |
| `description` | `string` | No | |

| `is_validation_enabled` | `boolean` | No | |

### `TestCredentialResponse`

| Field | Type | Description |
| --- | --- | --- |

## `POST /credentials`

Create a credential in Credential Hub.

| | |
| --- | --- |
| **Status** | **New** (today: websocket `CreateCredential`) |
| **Scopes** | `credentials:write` |

### Request body

```json
{
  "name": "Prod PB SFTP",
  "description": "Prime Broker production SFTP",
  "credential_type_id": 3,
  "is_shared": true,
  "is_default": false,
  "is_cloud_accessible": true,
  "data": [
    { "key": "Host", "value": "sftp.example.com" },
    { "key": "Port", "value": "22" },
    { "key": "Username", "value": "ops" },
    { "key": "Password", "value": "•••" }
  ],
  "roles": ["Operations"],
  "permissions": ["Operations_ReadWrite"]
}
```

### Response `201 Created`

`Credential` metadata only — **no `data` / secrets**.

```json
{
  "id": 412,
  "name": "Prod PB SFTP",
  "description": "Prime Broker production SFTP",
  "credential_type_id": 3,
  "credential_type_name": "FTP/SFTP",
  "is_shared": true,
  "is_default": false,
  "is_cloud_accessible": true,
  "is_validation_enabled": null,
  "frequency_id": null,
  "group_id": null,
  "is_valid": null,
  "validation_completed_on": null
}
```

### Example

```bash
curl -sS -X POST \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Prod PB SFTP","credential_type_id":3,"is_shared":true,"data":[{"key":"Host","value":"sftp.example.com"},{"key":"Username","value":"ops"},{"key":"Password","value":"•••"}]}' \
  "https://{tenant}.ryanplatform.com/api/v1/credentials"
```

### Legacy notes

- Websocket `CreateCredential` — PascalCase body; `Data` as key/value pairs on write only
- Server forces shared org credentials on create in today’s handler
- Emits event `CredentialCreated` (metadata / id — no secrets)

### Errors

| Status | Code | When |
| --- | --- | --- |
| `400` | `validation_error` | Missing name/type or invalid `data` |
| `403` | `forbidden` | No Credentials write access / cannot create |
| `409` | `conflict` | Name already used in org (when enforced) |

## `POST /credentials/{credentialId}/test`

Run a connection check (validate) for an existing credential.

| | |
| --- | --- |
| **Status** | **New** (today: websocket `ValidateUpdatedCredential` — also persists the body first) |
| **Scopes** | `credentials:write` |

### Path parameters

| Name | Type | Description |
| --- | --- | --- |
| `credentialId` | `integer` | Credential ID |

### Request body

Optional. Omit to test the stored credential as-is. If provided, fields match `UpdateCredentialRequest` and are applied before validation (matches today’s UI **Save & Validate**).

```json
{
  "is_validation_enabled": true,
  "frequency_id": 1,
  "group_id": 22
}
```

| Field | Type | Description |
| --- | --- | --- |
| *(any update fields)* | | When present, persist then validate (legacy behavior) |
| *(empty body)* | | Preferred v1: test stored settings only |

### Response `200 OK`

Validation outcome only — **no credential secrets**.

```json
{
  "credential_id": 412,
  "is_valid": true,
  "validation_completed_on": "2026-07-11T17:05:00Z",
  "message": null
}
```

### Example

```bash
curl -sS -X POST \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}' \
  "https://{tenant}.ryanplatform.com/api/v1/credentials/412/test"
```

### Legacy notes

| UI action | Websocket op | Behavior |
| --- | --- | --- |
| **Create & Validate** | `ValidateCredential` | Creates, then schedules/runs validation (`frequency_id` `1` or `2` → on schedule) |
| **Save & Validate** | `ValidateUpdatedCredential` | Updates, then schedules/runs validation |

v1 `POST …/test` should prefer **test without requiring a full recreate**. Create-and-validate can stay as `POST /credentials` followed by `POST /credentials/{id}/test`, or a future `?validate=true` on create.

Validation runs on a Bridge for supported types. List/detail surfaces show `is_valid` and `validation_completed_on` after completion (`CredentialStatusUpdated` event today). Those surfaces also return **metadata only** — never secret field values.

### Errors

| Status | Code | When |
| --- | --- | --- |
| `404` | `not_found` | Unknown ID |
| `400` | `validation_error` | Type does not support validation |
| `502` | `upstream_error` | Bridge could not complete the check |
| `403` | `forbidden` | No write access |
