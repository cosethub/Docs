# Data monitors

Configure and read **database table/view data monitors** — conditions on warehouse entities, status codes, trigger jobs, and alerts.

> **Base:** `/api/v1`  
> **Auth:** `Authorization: Bearer {token}`  
> **Scopes:** `data-monitors:read` / `data-monitors:write`  
> Product UI: [Data monitors](/warehouses/data-monitors)

Today these operations run through ProcessServer. Public REST wraps them under `/warehouses/.../data-monitors` and `/data-monitors/*`. Alert delivery to external systems uses [Webhooks](./webhooks) (`data_monitor.alert.*`).

---

## Concepts

| Resource | Description |
| --- | --- |
| **Monitor type** | Schema for one warehouse table/view (`warehouse_id` + `entity_name` + fields). Ensured on first save |
| **Data monitor** | Named instance on a type (conditions, escalation group, optional bridge) |
| **Condition** | Rule tree + `status_code_id` + optional `trigger_job_id` |
| **Alert** | Fired when a row matches a condition during warehouse write/delete |

Evaluation is **on data change** (create / update / delete for that entity), not a full-table schedule poll.

## Shared types

### `DataMonitorType`

| Field | Type | Description |
| --- | --- | --- |
| `id` | `integer` | Type ID |

| Field | Type | Description |
| --- | --- | --- |

### `DataMonitor`

| Field | Type | Description |
| --- | --- | --- |
| `id` | `integer` | |

| `data_monitor_type_id` | `integer` | |
| `warehouse_id` | `integer` | |
| `escalation_path_group_id` | `integer \| null` | Notification / escalation group |
| `owner_user_id` | `integer \| null` | |

### `DataMonitorCondition`

| Field | Type | Description |
| --- | --- | --- |
| `id` | `integer \| null` | Null on create |
| `status_code_id` | `integer` | Status emitted on match |
| `trigger_job_id` | `integer \| null` | Workflow / job tree to run (`JobTreeId`) |
| `rules` | `FilterGroup` | Condition tree |

### `FilterGroup` / `FilterRule`

```json
{
  "relation_to_previous": "and",
  "groups": [
    {
      "field": "marl",
      "operator": "=",
      "value": "0",
      "relation_to_previous": "and"
    }
  ]
}
```

| Field | Type | Description |
| --- | --- | --- |
| `field` | `string` | Column / field name |
| `operator` | `string` | e.g. `=`, `<>`, `>`, `is null` |
| `value` | `string \| number \| null` | Comparison value |
| `relation_to_previous` | `string` | `and` / `or` |
| `groups` | `array` | Nested rules or groups |

### `StatusCode`

| Field | Type | Description |
| --- | --- | --- |
| `id` | `integer` | |
| `name` | `string` | e.g. `Data Monitor Alert` |
| `severity` | `string \| null` | When exposed |
| `is_system` | `boolean` | Seeded vs org-defined |

System seeds commonly include Information, Ok, Warning, Alert, Critical, and Error.

### `DataMonitorAlert`

| Field | Type | Description |
| --- | --- | --- |
| `id` | `integer` | |
| `data_monitor_id` | `integer` | |
| `condition_id` | `integer` | |
| `status_code_id` | `integer` | |
| `message` | `string` | |
| `monitored_at` | `string` | ISO 8601 |
| `warehouse_id` | `integer` | |
| `entity_name` | `string` | |
| `source_row` | `object` | Row (or projection) that matched |
| `key_values` | `object` | Key fields / condition description bag |
| `response_status` | `string` | e.g. `open`, `acknowledged`, `closed` |

### `POST /warehouses/{warehouseId}/entities/{entityName}/data-monitors`

Create a monitor (ensures type if needed when `columns` are provided).

| | |
| --- | --- |
| **Status** | Planned (today: `SaveDataMonitor` + type create) |
| **Scopes** | `data-monitors:write` |

#### Request body

```json
{
  "name": "BBG price repair — marl zero",
  "description": "Alert when repair view shows marl = 0",
  "escalation_path_group_id": 15,
  "columns": [
    { "name": "marl", "data_type": "int" },
    { "name": "symbol", "data_type": "varchar" }
  ],
  "conditions": [
    {
      "status_code_id": 25,
      "trigger_job_id": 1042,
      "rules": {
        "relation_to_previous": "and",
        "groups": [
          {
            "field": "marl",
            "operator": "=",
            "value": "0",
            "relation_to_previous": "and"
          }
        ]
      }
    }
  ]
}
```

#### Response `201 Created`

`DataMonitor` including condition ids.

### Example

```bash
curl -sS -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"BBG price repair — marl zero","escalation_path_group_id":15,"conditions":[{"status_code_id":25,"trigger_job_id":null,"rules":{"relation_to_previous":"and","groups":[{"field":"marl","operator":"=","value":"0","relation_to_previous":"and"}]}}]}' \
  "https://{tenant}.cosethub.com/api/v1/warehouses/7/entities/ref.v_bbg_price_repair/data-monitors"
```

## Webhooks

When a condition matches, subscribe to:

| Event | When |
| --- | --- |
| `data_monitor.alert.created` | New alert from a table/view monitor |
| `data_monitor.alert.updated` | Alert acknowledged / closed (when exposed) |

See [Webhooks & events](./webhooks) for subscription, signatures, and full payload examples. In the product UI, the same fire also drives escalation-path email / SMS / in-app alerts and optional **trigger jobs**.
