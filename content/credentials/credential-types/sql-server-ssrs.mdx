# SQL Server - SSRS

Credentials for running SQL Server Reporting Services reports.

| | |
| --- | --- |
| **Group** | Database |
| **Where you create it** | Credential Hub → Create Credential |
| **Commonly used by** | SSRS Report Run |

## How it works

1. Enter report server URL, data source, and SSRS user details.
2. Optionally allow unvalidated SSL or Geneva report options.
3. Select on SSRS Report Run.

## Connection Settings fields

| Field | Description |
| --- | --- |
| **Report Server URL** | SSRS web service / report server URL (for example `https://reports.firm.com/ReportServer`). |
| **Data Source Name** | Shared or report data source name on the report server when the job must bind credentials to a specific source. |
| **User Name** | Login used to connect to the report data source (database or Windows user as configured). |
| **Password** | Password for the data source user. |
| **SSRS Server Domain** | Windows domain for SSRS authentication when the report server expects DOMAIN\\user. |
| **SSRS User Name** | SSRS / Windows user that runs or retrieves the report on the report server. |
| **SSRS Password** | Password for the SSRS user. |
| **Allow Unvalidated SSL Certificates?** | When on, accept TLS certificates the Bridge cannot validate (dev/self-signed only — avoid in production). |
| **Use for Geneva Reports?** | When on, use this SSRS credential for Geneva-related reporting paths that pull via SSRS. |

## In a job

On **SSRS Report Run**, pick this SSRS credential. You can also use **Add New … Credential** from some job forms when available.
