# Manage credentials in the product

Day-to-day Credential Hub work in the Ryan Platform UI — find the hub, read status, share, validate, edit, delete, and pick credentials from jobs.

For a first create walkthrough, see [Getting started](./getting-started). For REST, see [Credentials API](/api/credentials).

## How to open Credential Hub

Use any of these paths (same hub).

### From Administration

1. In the main nav, open **Administration**.
2. Find the **Security & Credentials** section (*Control authentication, authorization, and secure credentials.*).
3. Open the **Credential Hub** card (*Secure repository for logins, encryption keys, and connection details.*).

You land on the credential list at `/workflow/admin/credential-hub`.

{/* SCREENSHOT: Admin → Security & Credentials → Credential Hub */}

### From user settings

1. Open **User Settings** from your user menu.
2. Choose **Your Credentials**.

Requires Administration access. Same list as the admin card.

### From a job or warehouse form

1. Open a job (or warehouse setting) that needs a connection.
2. Find the credential dropdown (for example **FTP Server Credentials**).
3. Follow the hint **Managed in Administration -> Credential Hub** — it opens the hub (or the selected credential’s details if one is already chosen).
4. Or choose **Add New … Credential** at the bottom of the picker to create in a sidebar without leaving the job.

## Find something on the list

The hub list is the home screen for management.

| What you need | Where to look |
| --- | --- |
| Search by name, description, or type | **Search credentials** box at the top |
| Limit to one type (for example FTP/SFTP) | **Filter Credentials** → pick a type, or **All Credentials** |
| See how many you have | Footer **Total Credentials: …** |
| Open one credential | Click the row (name, type, description, validation status) |
| Create | **Create Credential** (or empty-state **Create a New Credential**) |

Each row shows:

- **Name**, **type name**, optional **description**
- Validation: **Last validated: …** (green/red by last result) or **Not validated**

There is no row-level Edit/Delete — open the credential first.

## Find details on a credential

1. From the list, click a row → **Credential Details** (read-only form).
2. Scroll the three cards:

| Card | What it holds |
| --- | --- |
| **Basic Information** | Name, type, share, default, description |
| **Connection Settings** | Type-specific fields (host, user, password, OAuth tokens, …) |
| **Validation & Permissions** | Last validated / last updated, validate toggle, frequency, notification group, groups |

3. From the bottom bar (if you have Credentials ReadWrite and the credential is not read-only):
   - **Edit** → change fields → **Save** or **Save & Validate**
   - **Delete** → confirm `Are you sure you wish to delete "{Name}"?`

## Find and change sharing / default

**Where:** Credential → **Basic Information** (view or edit).

| Setting | Label | How to find / use |
| --- | --- | --- |
| Share with org | **Share Credential with Organization?** | Toggle on so other users and jobs can select it |
| Org default for this type | **Set as Default Credential** | Toggle on; turning default **on** forces share **on**. Turning share **off** clears default |
| Override existing default | Dialog on create | If another default exists for the type: *A default already exists…* → **Confirm** |

Only owners / admins can change share on an existing credential in typical setups. Prefer shared credentials for production workflows.

## Find validation status and health checks

### On the list

Look at the right side of each row:

- **Last validated: …** — bridge has checked this credential; color reflects last success/failure
- **Not validated** — never validated (or no completed check yet)

### On the detail / edit form

1. Open the credential.
2. Go to **Validation & Permissions**.
3. At the top, find **Validate Credentials:** and either:
   - **Last Validated: …** with status indicator, or
   - **Last Updated: …** on view/edit when that is what the form shows

### Turn validation on

1. **Edit** the credential (or set this while creating).
2. Under **Validation & Permissions**, turn on **Validate Credential**.
3. Set **Frequency** to **Daily** or **Weekly**.
4. Optionally set **Notification Group** (who gets failure notices).
5. Choose **Save & Validate** (edit) or **Create & Validate** (create) to check immediately.

**Create & Validate** / **Save & Validate** only appear when **Validate Credential** is on.

Not every type supports bridge validation. If the controls stay disabled or validate fails with a type error, use a manual connection test outside the hub or check that type’s [credential type](./credential-types) page.

## Find who can use a credential (groups)

1. Open the credential → **Edit**.
2. Scroll to **Validation & Permissions** → **Groups and Permissions**.
3. If empty, you see **No groups.**
4. Choose **Add Group**, pick a group, set **Permission Level**.
5. Remove a group with the remove control on that row.
6. **Save**.

Job pickers still require the credential to be shared (or yours) and the correct type; groups refine who may manage or use it beyond the share toggle.

## Find OAuth login / refresh (Microsoft & Google)

1. **Create Credential** (or **Edit** an existing OAuth credential).
2. Set **Credential Type** to Microsoft OAuth or Google OAuth.
3. In **Connection Settings**, use:
   - **Login** — opens the provider login (*Please login to your … account and grant access to CoSet.*)
   - **Refresh credential details** — pull tokens again after access is granted
4. After success, confirm fields such as Token Type, Scope, Access Token, Refresh Token are populated.
5. **Create** / **Save**.

If you see *Login URL is not available.*, the org/bridge is not configured for that OAuth type — contact an admin.

## Find a credential from a workflow job

1. Open **Workflow Automation** → open the workflow → select the job.
2. In job fields, look for the credential control (label varies by type):

| Job need | Typical field label |
| --- | --- |
| SFTP / FTP | **FTP Server Credentials** |
| Mailbox watch | **Credential** (IMAP) |
| Outbound email | SMTP-related credential field |
| SQL load / warehouse | Often on the **warehouse**, not the job — see [SQL for warehouse](./examples/sql-warehouse) |

3. Open the dropdown → pick by **name**, or **Add New … Credential**.
4. To jump to hub management: use **Managed in Administration -> Credential Hub**.

---

## Find SQL credentials used by warehouses

SQL Server / PostgreSQL credentials for **Table to CSV** and warehouse access are usually attached on the **data warehouse**, not on each export job.

1. Open the warehouse (Databases / warehouse settings for your org).
2. Find the staging / warehouse account credential fields.
3. Select or create the SQL credential there.

Details: [SQL for warehouse / Table to CSV](./examples/sql-warehouse).

## Edit checklist

| Step | Where |
| --- | --- |
| 1. Open hub | **Administration** → **Security & Credentials** → **Credential Hub** |
| 2. Find the row | **Search credentials** / **Filter Credentials** |
| 3. Open details | Click the row |
| 4. Edit | **Edit** |
| 5. Change basics | **Basic Information** |
| 6. Change secrets/host | **Connection Settings** |
| 7. Change health checks / groups | **Validation & Permissions** |
| 8. Persist | **Save** or **Save & Validate** |

Notes:

- On edit, **Credential Type** is locked (change type only by creating a new credential).
- Read-only credentials: **Edit** stays disabled.
- Unresolved form warnings block save (*There are unresolved warnings.*)

---

## Delete checklist

1. Hub list → open the credential.
2. **Delete**.
3. Confirm the dialog.
4. You return to the list; that name disappears from job pickers.

You need Credentials ReadWrite. Delete is blocked for read-only credentials or when you lack permission.

---

## Permissions you need

| Action | Permission |
| --- | --- |
| Open hub via Administration / Your Credentials | Administration access (for the menu entry) |
| Create / Edit / Delete / Validate | **Credentials** ReadWrite |
| Pick a shared credential in a job | Job access + credential shared (or owned by you) |

If **Create Credential** is disabled, ask an admin for Credentials ReadWrite.
